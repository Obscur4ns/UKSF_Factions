# 1. Purpose

This document provides the first practical Persian-language content pool for Karzeghistan.

It is intended to support:

- Arma identity pools;
- KDF/KNP/KBG naming;
- SPF terminology;
- government signage;
- police and border markings;
- road/border props;
- briefings and intelligence products;
- future texture production.

Every important permanent form should be stored as:

```text
Persian
Operational Latin
English
```

The pool is deliberately broad and contemporary. It is **not** a demographic census and does not imply that every listed name is equally common.

# PART I — LANGUAGE & ROMANISATION RULES

## 2. Locked Language

```text
Karzeghistan → Persian
```

Project descriptor:

```text
Karzeghistani Persian
```

Existing Armaverse Latin spellings remain authoritative in English/editor use.

## 3. Operational Romanisation

Use the existing UKSF simplified system:

```text
خ → kh
غ → gh
ش → sh
ژ → zh
چ → ch
ق → q
```

Scholarly vowel marks are removed in normal project text.

## 4. Ezafe

Player-facing operational spelling uses:

```text
-e
-ye
```

rather than scholarly `-i / -yi`.

This keeps new project names visually compatible with:

```text
Shapur e-Dalanper
```

## 5. Config Rule

Classnames and filenames remain ASCII.

Do not use:

- Persian script;
- scholarly diacritics;
- RTL text;

inside public Arma classnames.

## 10. Usage Notes

### `پلیس`

Use for ordinary police identity.

### `مرزبانی`

Use for the border-service institution.

### `گمرک`

Use for Customs.

Do not merge:

```text
مرزبانی
and
گمرک
```

into one service merely because both appear at border crossings.

### `ایست بازرسی`

Useful for general security checkpoints.

### `گذرگاه مرزی`

Use for an official border crossing.

### `پاسگاه مرزی`

Use for a border-security post/station rather than the crossing itself.

# PART VII — PERSONAL NAME MODEL

## 17. Arma Display Format

Default:

```text
Given Name + Family Name
```

Example structure:

```text
Arash Rahimi
Maryam Karimi
```

These examples show formatting only.

## 18. Name-Pool Principle

The pool deliberately mixes:

- Persian-origin names;
- Arabic-origin names common in Persian usage;
- names established broadly across Persian-speaking society.

It should not be read as:

```text
ethnic census
religious census
frequency ranking
```

## 19. Avoid Over-Theming

Do not make every KDF soldier:

- ancient-royal themed;
- Shahnameh themed;
- overtly Iranian-nationalist themed.

Likewise, do not make every character carry an Arabic-origin name.

Variety is the desired result.

# PART XI — FAMILY-NAME GUIDANCE

## 23. Surname Use

Family names are normal for the project's Karzeghistani identity format.

Use one stable transliteration for each family name.

Do not alternate between forms such as:

```text
Rezaei
Rezai
Reza'i
```

for the same project surname entry.

The approved project form is whatever appears in this pool.

## 24. Geographic Surnames

The first pool deliberately avoids heavy use of surnames derived from real Iranian cities or provinces.

Reason:

> Karzeghistan should sound Persian-speaking without constantly pointing the player toward real Iran.

Future fictional Karzeghistani place-derived surnames may be added after more local geography exists.

## 25. Compound Surnames

Compound family names can exist later.

For first-release Arma identities, simple surnames are preferred because they:

- read cleanly in the UI;
- avoid punctuation inconsistency;
- reduce duplicate transliterations.
